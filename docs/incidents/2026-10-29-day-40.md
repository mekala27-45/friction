# Postmortem: replay day 40 of the payments desk

> friction is a portfolio demonstration built on two published synthetic data sets (the IBM TabFormer card transactions, and the RBA login data set under CC BY 4.0) and a simulator with known truth. No real person, card or account appears in it, its numbers describe synthetic data, and it must not be used to decide anything about anyone. It runs on Databricks Free Edition, which is for non commercial use.

Blameless. The fault was planted (config/incident.yaml); everything after the plant was handled as
if it were not.

## Summary

Drop 0387_2020-01-07 arrived as three files: the previous day's file sent again, one part
with a column renamed upstream, and one part with every timestamp six hours ahead. The deduplication
held: no transaction of the resent file was counted twice. The renamed column's rows landed in rescued
data and were quarantined; the shifted rows broke the clock rule. Before the fix the drop put
2,442 transactions worth $109,455.08 into silver against
5,849 worth $275,274.70 in the corrected source, and the
completeness of the drop was 70.20%.

## Detection

The monitor job in the workspace, over every backfilled row, raised these alerts on the drop, and the
workspace workflow opened GitHub issue 1 from them:

What detected it: the completeness objective and the clock check, in the first monitor run after the
backfill that carried the drop. What did not: no total in a monthly chart moves enough to notice in a
day, and the resend set off nothing because nothing was lost. The same run also flagged drift in
device_type, mcc_fraud_rate across the later months against the training months; that is the label
calendar of TabFormer, not this incident, and it stays open on its own.

## Root cause

Upstream renamed a column in one part of the extract without a contract change, and a clock fault
shifted the other part; the same day's previous file was resent by a retry in the delivery job.

## Response, following docs/runbooks/ingestion.md

- Identify: the quarantine by rule and file, and the run log, named the two faulty files.
- Contain: the daily job has never been scheduled in this workspace, so no later drop stacked on top;
  nothing in bronze was touched.
- Fix: an approved contract change in contracts/approved_changes.yaml (DECISIONS.md, The day 40
  contract change) reads the renamed column back out of rescued data and rejects the shifted part; the
  corrected file was redelivered.
- Replay: the drops around the day on open source Spark, before and after the change, and in the
  workspace a backfill of the drop with the redelivery.

## Actions

- A schema change notice from upstream becomes a required step before any column rename ships.
- The clock check runs at land time on each file, before the pipeline, so a shifted file never reaches
  bronze unflagged.
- The resend is caught at land by a digest of each file against the files already landed, so the
  deduplication is the second line, not the only one.
